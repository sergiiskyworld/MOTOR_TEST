# Стенд тяги двигателя

Управление оборотами мотора на испытательном стенде: полётный контроллер
**Orqa F405 Pro** работает программируемым генератором сигнала для ESC, а
регулировка и телеметрия живут в браузере.

Полётный контроллер заменяет сервотестер. В отличие от сервотестера он умеет
DShot, читает телеметрию из ESC (обороты, ток, напряжение, температура) и
останавливает мотор сам, если связь с компьютером пропала.

```
браузер  ──WebSocket──►  Python-сервер  ──USB CDC──►  Orqa F405 Pro  ──PWM/DShot──►  ESC (AM32)
                                                             ▲                            │
                                                             └────── телеметрия ──────────┘
```

[«Первое включение»](docs/SAFETY.md#первое-включение).

## Быстрый старт

### 1. Прошить полётный контроллер

```bash
./scripts/flash.sh
```

Скрипт собирает прошивку, ждёт появления платы в DFU, снимает резервную копию
текущего содержимого флеша в `firmware/backup/` и только потом пишет новую.

Войти в DFU: зажать кнопку **BOOT** на плате и, не отпуская, воткнуть USB.
Программного способа нет — проверено на железе, подробности и что именно
пробовалось в [docs/FLASHING.md](docs/FLASHING.md).

> Прошивка занимает всю флеш-память и стирает то, что стояло раньше
> (Betaflight или ArduPilot) вместе с их загрузчиком. Восстанавливается из
> резервной копии тем же DFU.

### 2. Подключить провода

Минимум три провода до ESC плюс один для телеметрии —
[docs/WIRING.md](docs/WIRING.md).

### 3. Настроить ESC

В конфигураторе AM32 обязательно включить отдачу телеметрии по интервалу,
иначе показания в интерфейсе останутся пустыми —
[docs/ESC_AM32.md](docs/ESC_AM32.md).

### 4. Запустить интерфейс

Двойной клик по **`Prog/START-MAC.command`** на macOS или по
**`Prog/START-WINDOWS.bat`** на Windows — и всё: при первом запуске создаётся
окружение Python, поднимается сервер, открывается отдельное окно браузера на
весь экран, без вкладок и адресной строки. Подробности, структура папки и
решение частых проблем — [docs/LAUNCH.md](docs/LAUNCH.md).

Всё, что нужно приложению, лежит внутри `Prog/`: сервер, окружение и файлы
запуска. Наружу вынесены только прошивка, скрипт заливки и документация.

Сервер слушает все интерфейсы, так что с телефона в той же сети страница
доступна по IP компьютера. При первом запуске macOS спросит разрешение на
входящие соединения — это нормально.

USB-порт занят только пока открыто окно стенда в браузере, и освобождается
через три секунды после закрытия последнего окна — либо после того, как
страница просто замолчала, что покрывает упавший браузер и уснувший телефон.
Поэтому конфигураторы AM32 и ArduPilot остаются работоспособными — почему так
сделано и какой ценой это выяснилось, описано в
[docs/PORT_SHARING.md](docs/PORT_SHARING.md).

Сервер можно поднять и вручную:

```bash
cd Prog
python3 -m venv .venv && .venv/bin/pip install -r server/requirements.txt
.venv/bin/python server/run.py
```

Порт платы определяется автоматически по USB VID/PID. Если плат несколько:
`.venv/bin/python server/run.py --serial-port /dev/tty.usbmodem1234`.

### Без железа

```bash
.venv/bin/python server/run.py --simulate
```

Поднимает программную модель платы с правдоподобной телеметрией: можно
посмотреть интерфейс, прогнать автотест и проверить логику защит.

## Возможности

- **Протокол**: DShot300. Регулятор принудительно переведён в DShot в своих
  настройках, поэтому плата поднимается в DShot при каждом включении, а выбор
  протокола из интерфейса убран, чтобы нельзя было рассогласовать стороны.
  Серво-PWM и другие частоты DShot в прошивке остались и переключаются
  командой `P`, см. [docs/PROTOCOL.md](docs/PROTOCOL.md).
- **Телеметрия ESC**: обороты, напряжение, ток, температура, израсходованная
  ёмкость — из AM32 по отдельному проводу, плюс независимые замеры напряжения
  и тока с датчиков самой платы.
- **Сила тяги**: отдельное показание и своя линия на графике. Датчик к плате
  ещё не подключён, поэтому пока показывается прочерк; формат данных от
  прошивки уже описан в [docs/PROTOCOL.md](docs/PROTOCOL.md), а пересчёт
  отсчётов в граммы делает сервер.
- **Калибровка по внешнему прибору** — шестерёнка в шапке страницы. Вписанные
  показания мультиметра, токовых клещей и эталонного груза пересчитываются в
  поправки: напряжение и ток правятся в самой плате и записываются в её
  флеш-память, поэтому переживают выключение питания и действуют на токовую
  отсечку тоже.
- **Автотест по ступеням**: проходит заданный список значений газа с выдержкой
  на каждой ступени и пишет CSV — то, ради чего стенд и нужен.
- **Запись в CSV** с оборотами, током, мощностью, тягой и меткой ступени.
- **Защиты**: отсечка по току и температуре, ограничение газа, ограничение
  скорости нарастания, аварийный стоп с фиксацией.

## Безопасная остановка

Цепочка «мёртвого человека» протянута от браузера до мотора: страница шлёт
пульс каждые 100 мс, сервер ретранслирует его в плату только пока пульс идёт, а
прошивка глушит мотор, если тишина длится дольше 300 мс.

Поэтому мотор останавливается сам при закрытии вкладки, потере Wi-Fi,
зависании браузера, падении сервера и отключении USB. Подробно —
[docs/SAFETY.md](docs/SAFETY.md).

## Структура

```
firmware/            прошивка полётника (PlatformIO, STM32duino)
  include/config.h     распиновка, тайминги, значения по умолчанию
  include/protocol_bits.h  кодирование DShot, CRC телеметрии, пересчёт газа
  src/motor_out.cpp    выходы M1/M3: PWM и DShot через DMA
  src/esc_telem.cpp    приём телеметрии AM32 по UART5
  src/main.cpp         состояния, защиты, протокол обмена с компьютером
  include/sense_filter.h   фильтр аналоговых входов
  include/esc_stream.h     отбор пакетов своего регулятора на общей линии
  test/                нативные тесты битовой логики и арифметики
Prog/                всё для запуска приложения
  START-MAC.command        запуск на macOS — клик здесь
  START-WINDOWS.bat        запуск на Windows — клик здесь
  launcher/                механика запуска и остановки, см. docs/LAUNCH.md
  server/standserver/link.py   последовательный порт
  server/standserver/sim.py    модель платы для работы без железа
  server/standserver/main.py   FastAPI, WebSocket, автотест
  server/standserver/calibration.py  поправки по внешнему прибору
  server/standserver/static/   интерфейс
  server/tests/smoke_test.py   сквозные проверки
scripts/
  flash.sh                 сборка и заливка прошивки через DFU с резервной копией
docs/                описание подключения, прошивки, протокола и безопасности
```

## Восстановить то, что стояло на плате раньше

`scripts/flash.sh` перед каждой заливкой сохраняет полный дамп флеша в
`firmware/backup/`. Вернуть исходную прошивку вместе с её загрузчиком:

```bash
~/.platformio/packages/tool-dfuutil/bin/dfu-util -d 0483:df11 -a 0 \
    -s 0x08000000:leave -D firmware/backup/before-flash-ГГГГММДД-ЧЧММСС.bin
```

Сама папка в репозиторий не выгружается — это выход инструмента, по мегабайту
на каждую заливку. Исключение одно: `before-flash-20260923-143608.bin`, самый
первый дамп. В нём то, что стояло на плате до нас, и другого источника для него
уже не будет.
